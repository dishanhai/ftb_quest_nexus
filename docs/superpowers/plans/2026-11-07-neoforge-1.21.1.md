# NeoForge 1.21.1 Implementation Plan

> **For agentic workers:** 使用 executing-plans 與 dispatching-parallel-agents，按檔案所有權執行及檢查。未授權 Git commit，僅保留本地變更。

**Goal:** FTB Quest Nexus 與外部 SH-Better-UI 同步提供 NeoForge 1.21.1 產物，保留 Forge 1.20.1。

**Architecture:** 兩庫新增獨立 `neoforge/` 建置。純 Java／Kotlin 邏輯及圖片／語言共用，Minecraft／loader API 差異以平台來源覆寫。先完成依賴與 UI，再整合提交器。

**Tech Stack:** Java 21、NeoForge 21.1、ModDevGradle、Minecraft 1.21.1、AE2 19、FTB Quests 2101、KotlinForForge NeoForge、JUnit 5、GameTest。

## 執行與檔案責任

- [x] 建置：Nexus `neoforge/build.gradle`、`settings.gradle`、`gradle.properties`、`src/main/resources/META-INF/neoforge.mods.toml`，固定官方依賴，產物區分平台。先執行 `compileJava` 留存不相容 API 診斷，再修正。
- [x] UI：SH-Better-UI `neoforge/`，共用純動效測試，移植入口、事件與渲染適配，執行 `test build`。
- [x] 核心：Nexus `neoforge/src/main/java/.../submitter/` 與 `gametest/`，移植 registry lookup 保存、data components、AE 節點、FTBQ 任務與獎勵 API。先移植既有 GameTest，驗證會抓出不相容或資料遺失，再完成實作並重跑。
- [x] 互動：Nexus NeoForge 入口、註冊、客戶端、network、Mixin、Jade。明確單向 payload 與上限、伺服器隊伍／位置驗證，client 類別不得進入 common entry 初始化。
- [x] 整合：使用 UI NeoForge jar 作外部依賴，執行 Nexus `test build runGameTestServer`；檢查生存掉落與創造模式複製、綁定隊伍、獎勵重試、AE 身分。
- [x] 回歸與交付：兩庫根目錄 Forge `test build`，記錄每個 jar SHA256、測試數與未做實機驗證於 `docs/neoforge-verification.md`；更新兩庫 README 與 TODO。

## 執行環境

PowerShell 設定 `JAVA_HOME=C:\Program Files\Java\jdk-21.0.11`、`TEMP=C:\jtmp`、`TMP=C:\jtmp`。NeoForge 使用自己的 Gradle wrapper（版本以官方 MDK 要求為準），不讓 ModDevGradle 與根 ForgeGradle 共存同一個 configuration。

## 測試要求

共用 TaskQueue／FtbqRewardBuffer／ToastSuppressor／HeaderButtonLayout 測試驗證不變語義。GameTest 實際測試 ItemStack 保存、掉落、UUID、AE node owner 與 FTBQ TeamData／ItemTask／ItemReward。兩個正式 jar 不內嵌 Kotlin、UI 或 AE／FTB 相依 class，不包測試類。所有錯誤修正集中記錄於 `.learnings/ERRORS.md`，未完成工作列 TODO。
